## Bootstrap

**Ask, don't read.** Reads go through the local MCP servers first; the
filesystem is the fallback. Canonical rule:
`methodology/distributed-work.yaml` → `mcp_first_read_path`.

- `forge-plan` / `project-plan` — `plan_answer`, `plan_next`, `plan_query`,
  `plan_status`, `plan_blocked_by`, `methodology_ask`, `methodology_path`,
  `spec_answer` — fast sub-100ms cited answers over `plan/index.yaml` and
  methodology rules.
- `project-info` — `search_code`, `grep_code`, `find_files`, `file_summary`,
  `read_file`, `git_status`, `project_structure` — repository files.
- Local Experts mode (`local-experts` agent → grounded `expert-serve`) for
  conversational status: citations or a typed `unsupported:` refusal, never
  raw-model prose; on refusal or degraded `experts_state`, fall back to the
  `plan/` files and say so.

Good first questions: *"what is the current Direction?"*, *"what's next?"*.

Fall back to reading files for exactly three reasons, and name the one that
applies: **unavailable** (MCP down or `confidence=unsupported` — fall back and
keep going, then record it), **verification** (before anything irreversible,
read the cited span — the span, not the file), **not exposed** (no tool covers
it; if the loop needs it repeatedly, that is a missing tool — file a packet).

If `.forge-startup-context.md` exists in the repository root, you are inside a
Tillandsias forge container — read it for live infrastructure state.

**IN A FORGE, A FINDING YOU DID NOT PUSH IS A FINDING YOU DESTROYED.** That
workspace is a `git clone` into the container and dies with it. Writing a
fragment to `plan/index.d/` and validating it with `tillandsias-plan check`
proves it is well-formed, not that it survives. On 2026-08-15 an in-forge review
filed three valid fragments, the ledger accepted them, and teardown took all
three; they reached the ledger only because a human was reading stdout (order
741-3y48). Commit and push every finding before exiting — push routes through the
enclave mirror and needs no configuration — then prove it with
`scripts/check-forge-findings-persisted.sh` (a GATE: `unpersisted:<why>` means
work already done is about to be thrown away; a cycle that filed nothing prints
`ok:no-findings` and is silent). If you truly cannot push, reproduce every
finding in full in your final output rather than exiting quietly.

This rule lives HERE, in the checkout, on purpose: the startup context is
generated by a script baked into the forge image, so a warning added there
reaches running forges only after an image rebuild — and for a fail-loud guard
that delay is the whole failure (order 743-y5wh). Checkout-level instructions are
current in every forge the moment they are pushed.

**UX IS LOCKED**: never add, remove, or alter ANY user-visible UX surface
(menus, labels, chips, notifications, dialogs) without explicit operator
approval recorded in the plan ledger. UX is for end users who know nothing
about VMs/WSL/enclaves/mirrors — not for agents, not for the operator.
Canonical rule: `openspec/specs/tray-ux/spec.md` → "UX curation governance".

**Before EVERY push**: run `./build.sh --check` and fix what it reports. An
unparseable or unformatted push poisons every downstream clone (see
`plan/issues/agent-pushed-unparseable-code-no-push-ci-2026-07-21.md`); push CI
no longer exists on any working branch (only the manually-dispatched release
workflow remains, litmus:github-actions-budget), so this local gate is the only
trunk protection.

## Platform Branch Coordination

- Linux checkpoints to `linux-next`.
- Windows checkpoints to `windows-next`.
- macOS checkpoints to `osx-next`.
- Before platform-branch work, fetch/pull the active branch and record sibling
  heads for `main`, `linux-next`, `windows-next`, and `osx-next`.
- Before fast-forwarding a platform branch, verify the remote platform head is
  an ancestor of the source ref.
- Before EVERY push of a non-linux-next branch, merge `origin/linux-next` into
  it and resolve conflicts locally (methodology `pull_merge_cadence.pre_push_gate`).

Canonical details: `methodology/multi-host-development.yaml`.
