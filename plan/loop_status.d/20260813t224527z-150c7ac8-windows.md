## Cycle — windows (windows-next)

- Operator asked for signing in local builds AND github actions. Both wired to
  ONE seam (scripts/sign-windows-artifact.ps1); only the credential differs —
  AzureCliCredential locally, federated OIDC in CI. If the lanes diverged, what
  CI signs would stop being what a developer can reproduce.
- Signing is placed on the STAGED exe, before Compress-Archive and before the
  checksum. Signing after either would publish checksums for a file nobody can
  download, which reaches users as a checksum mismatch on a correctly signed
  binary — indistinguishable from a supply-chain attack.
- Gated on vars.TILLANDSIAS_SIGNING_ACCOUNT so the release lane keeps working
  until the Azure identity (722-w7a2) exists, and warns loudly when it publishes
  unsigned.
- Fixture 5/5 with a POSITIVE control, hand-falsified in both directions.
- THREE defects found in the fixture BY RUNNING IT, all the same family: a
  PowerShell-7-removed parameter that made the tamper a no-op while the test
  still passed; a source-order check that matched "Compress-Archive" inside the
  COMMENT explaining the ordering; and a fixture that printed PASS while exiting
  1. Every one would have read as green. Recorded on 722-qvqb.
- Not claimed: that a real signature is produced. That needs the account. What
  is proven is that every path which could silently ship unsigned refuses loudly.
