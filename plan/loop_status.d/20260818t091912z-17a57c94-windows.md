**THE CLAUSE.** Last cycle left 823-u5zf open on one unanswered question: `install -d -m 0700 "$XDG_RUNTIME_DIR"` needs a home that is not a shell. Auditing the preamble, every OTHER clause is `export NAME=value` — which an argv launch carries in its env map. This one is a side effect, and it is why a shell had to stay in the chain at all.

**THE TEMPTING READING WAS WRONG.** "Consumers already `create_dir_all` under that path, so the preamble clause is redundant" — no. `create_dir_all` creates missing parents at 0777-minus-umask, commonly **0755**. XDG_RUNTIME_DIR holds control sockets, so a world-traversable parent is a real weakening, not a cosmetic one. The MODE was load-bearing and nothing downstream replaces it. Deleting the clause as redundant would have silently loosened a permission with no test failing.

**RESOLUTION: the guarantee moved to the process that depends on it.** `tillandsias-headless` now asserts the directory at startup, before any subsystem derives a path under it (`ensure_xdg_runtime_dir`, `main.rs`). That removes the last reason a shell sits between the tray and the binary.

**Deliberately NON-FATAL.** Unset variable, or a create that fails → warn and continue; a create that succeeds but a chmod that fails still returns the path and says so. Every consumer already falls back when the runtime dir is absent, so refusing to start a lane over a directory *mode* would be a worse failure than the one being prevented.
