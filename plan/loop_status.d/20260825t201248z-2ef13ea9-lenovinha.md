credential changed.

This is the most normal state a cycle can enter the guard in: Start-Of-Cycle fetches at
step 2 and runs the guard immediately after, while the fast-forward is step 5. Any host
whose siblings pushed since its last cycle enters this arm by construction. Order
876-exg2 removed the same conflation one layer up (the local pre-push hook); its
`--no-verify` retry cannot rescue this one, because it removes the hook and not the
non-fast-forward, so both probes fail and the printed remedy is inert.

Fix takes ref state out of the question rather than pattern-matching the remote's
rejection text: on the failure path only, probe a unique ref under
`refs/tillandsias/cred-probe/<host>-<pid>`. A create is always fast-forwardable, so
authentication is the only thing left that can fail it. `--dry-run` means the ref is never
created (verified: `ls-remote` of that namespace stays empty). New verdict
`ok:gh-keyring-push-verified-refstate-refused`, exit 0.
