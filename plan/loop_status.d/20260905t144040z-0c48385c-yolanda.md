**The finding that would have cost a day.** TWO Microsoft APIs are called "the
Store submission API" and both rank highly for the same searches. The MSI/EXE one
takes a token scoped `https://api.store.microsoft.com/.default`; the MSIX/UWP one
— ours, since the operator deleted the EXE/MSI draft and created an MSIX listing
— takes `resource=https://manage.devcenter.microsoft.com`. **The wrong resource
mints a token that authenticates fine and then fails every call**, and the wrong
one is what a search surfaces first.

**The step most likely to be guessed wrong:** the packages do not go to the API.
`POST /applications/{id}/submissions` returns a `fileUploadUrl` which is an
**Azure Blob SAS URI**, and packages plus listing images go up as a **single ZIP**
written to that blob. Then `POST .../commit`, then poll `.../status`.

**`Published` is the only success state.** The chain runs PendingCommit →
CommitStarted → PreProcessing → Certification → Release → Published. A CI job
treating "not failed" as success reports green while a submission sits in
Certification for days.

**A prerequisite that corroborates rather than merely agrees.** The previous
agent recommended a MANUAL first submission before automating. The docs make it
mandatory: the API cannot create the app, and one submission must be completed in
Partner Center first — including the age-ratings questionnaire — before the API
can create any submission for it. Their judgement call turns out to be a
requirement, which is worth more than agreement.

**Costs and lead times, the half EC2 asked for.** $0 and no certificate.
Certification typically hours, up to THREE BUSINESS DAYS, then ~15 minutes to
visibility. Consequence for the release lane: **a Store release is not same-hour
reliable**, so anything blocking on `Published` must tolerate that worst case or
be decoupled from the release it accompanies.

**Four traps recorded**, the sharpest being that an API-created submission must
never be edited in Partner Center — it becomes uncommittable via the API and can
strand in a state recoverable only by delete-and-recreate. That forbids the
obvious debugging move of fixing it in the UI.

**Named as unmeasured rather than recommended:** Microsoft ships StoreBroker, an
open-source PowerShell module over this exact API, and our Windows build path is
already PowerShell. I did not assess its dependency weight or maintenance status,
so it is recorded as worth evaluating, not as a recommendation.
