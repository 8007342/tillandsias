**Three fixes, one root cause and two consequences.** A bounded `harness_update_lock_wait_acquire` turns the loser into a waiter instead of a racer (the winner is installing the same binary, so waiting is useful; the budget is finite because a lane must never hang on a harness update). `require_opencode` installs only while holding the lock and otherwise uses the sibling's cached binary — probed, not assumed. `curl_install_opencode` gives the vendor script a private TMPDIR it deletes unconditionally and sweeps stale `/tmp/opencode_install_*` trees; the sweep is **age-bounded so it can never delete a sibling's in-flight extraction**, which would be the same bug in the other direction. And the entrypoint's init-prompt guard tested `-w` (permission) when the failing condition was space, so a full tmpfs produced a bare `echo: write error` that never named `/tmp`; it now verifies the write landed and prints `df -h /tmp` and the cause.
