## Cycle - windows (windows-next)

- Closed 647-i98k. `--diagnose` exit 3 = CONVERGING, distinct from DEGRADED.
  The wire answered and the guest named an unfinished phase - a fact from the
  guest, not an inference from timing, which is why it earns its own code.
- THE RESTRAINT IS THE OTHER HALF: an unreachable wire stays exit 2, even
  though in the reported incident it was also merely converging. At probe time
  it is indistinguishable from genuinely broken, and calling it converging
  trades a false "broken" for a false "not ready yet" - the worse error,
  because it tells automation to keep waiting on something that may never
  arrive. The bounded-wait branch of criterion 1 is deliberately NOT taken.
- Consumers updated in the same commit, because a new exit code its own
  consumers do not know about is how a fix degrades the thing it fixed:
  tray-diagnose.ps1 printed "UNKNOWN (exit 3)" for an ordinary post-provision
  state; the diagnostics cheatsheet now documents retry-on-3, fail-on-2.
- NOT changed: --status-once. Its older contract (0/2/1) already separates
  converging from broken and has no conflation to fix; changing it for symmetry
  would break working scripts. The asymmetry is recorded in the cheatsheet.
