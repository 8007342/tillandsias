**THE CHANGE.** `/bin/bash -lc "export … && exec tillandsias-headless --cloud '<p>' --opencode"` becomes `/usr/local/bin/tillandsias-headless --cloud <p> --opencode`. The shell was only ever carrying environment setup, and all three pieces now live where they belong: the `install -d -m 0700` side effect was already `ensure_xdg_runtime_dir()`; the two exports became `ensure_lane_process_env()` this cycle; and `TILLANDSIAS_VAULT_API_BASE_URL` needed nothing because `vault_api_base_url()` already self-defaults in-VM.

**Established by reading, not assumed:** `PtyOpenOpts.env` carries only TERM/COLORTERM/LANG (audit D7) and the guest PTY handler `env_clear()`s the child, so the wire lane has no other channel for HOME/XDG_RUNTIME_DIR — and the Windows lane has none at all, since the tray spawns `wsl.exe` with `spec.argv` and drops `spec.env`. That is why the defaults had to go into the binary rather than the launcher. `argv[0]` is absolute for the same reason: `env_clear()` means a bare name would depend on the PATH the `-l` shell used to rebuild.

**A STALE PIN FOUND AND REPAIRED.** `project_lane_argv_is_never_routed_through_wt` hardcoded the old flattened argv "verbatim from tray.log" and asserted it was wt-unsafe. It kept **passing** after the product stopped emitting that string, while its name asserted the opposite of shipped behaviour — a pin that is true about something nothing builds any more says nothing about the product. Rewritten so the REAL argv must clear the predicate, with the legacy shape retained as a negative control proving the guard was not weakened to get that result.
