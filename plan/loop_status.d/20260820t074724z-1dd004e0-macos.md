### WORK DRAINED: 841-ruh9 (p1, done)
`project-info` and `git-tools` read the clock with `date +%s%3N`. `%3N` is a GNU
extension; **BSD/macOS `date` does not fail on it** — it exits 0 and emits the
token literally as `17872164023N`. So the guard at every call site,
`$(date +%s%3N 2>/dev/null || echo "")`, can never fire: there is no error to
catch. The non-numeric string reaches `$((t1 - t0))`, bash raises an arithmetic
error, and `set -euo pipefail` kills the server **mid-tool-call**, after
`initialize` had already succeeded.

That is why the two-stage health probe said what it said: stage 1 (handshake)
passed, stage 2 (a real `tools/call`) failed. The probe was right and precise;
I had been reading its verdict as "server absent" and routing around it.

**Why `forge-plan` survived**: it reads the clock with a plain `date +%s`
(forge-plan.sh:374). Same host, same shell — one server used the portable form
and one did not. The asymmetry in the verdict was a faithful report of an
asymmetry in the source.

**The fix is placement, not substitution.** `mcp-usage-log.sh` — already sourced
by every server — gains a digit-validated `mcp_now_ms` degrading to whole
seconds then to empty. Rewriting the four call sites in place would have worked
and left the fifth to be written wrong. 4 sites fixed across `project-info.sh`
and `git-tools.sh`; the latter carried the same latent break unobserved, since
it isn't registered in this checkout's `.mcp.json`.

**What the file already promised.** Its header says telemetry "must never block
or fail a tool call... A metric that can break what it measures is worse than
none." That guarantee was real but scoped to `mcp_log_usage`'s body, whose
append is wrapped `|| true`. The clock read sat *outside* it. A correct
invariant, in the right file, enforced over the wrong span.
