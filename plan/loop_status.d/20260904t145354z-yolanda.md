### 1004-vsh2 — cmdkey's header made the verifier always true

**Pre-fix result of each criterion, before the diff:** "verifier does not throw
on a clean store" — FAILS by construction (it threw on every run, including
immediately after a successful delete). "delete guard fires only on a credential
that exists" — FAILS by construction (fired for every target).

`cmdkey /list:<target>` echoes the target in its **header** even when nothing is
stored, so matching the escaped target is true unconditionally.

**The exit code does not discriminate** — cmdkey returns 0 for present *and*
absent. The suggested locale-proof status predicate does not exist; recorded as
a measured negative so the next person to have that idea finds it tested rather
than testing it again.

**Locale-proof by another route:** count the echoes of the *target name*, the
one string Windows does not localize. Header echoes once; a real record echoes
again on its `Target:` line. 1 = absent, ≥2 = present. Not "absence of
`* NONE *`" — that and the header are localized, and would trade a bug that
fails on every run for one that fails only on some operators' machines.

Proven both directions, then **proven again on the real §2 reset**: share and
token cleared, `tillandsias-vm-uuid` preserved, verifier did not throw.
