**THE FLAW, FOUND BY USING IT.** 808-7yrd's premise is *"single writer per key by construction, so LWW never arbitrates a real conflict."* On Windows that is **false** as originally keyed: a machine is observed from two contexts, both describing `yolanda`, both carrying the same `host_id`. Measured, not argued — contributing a Windows-side row **erased the guest row**:

```
before  host:yolanda  schedulable cpu/container, cpu/host-native; present-unusable gpu
after   host:yolanda  schedulable none;                           present-unusable npu
```

The cpu and gpu did not become unschedulable — they stopped being reported. Data loss dressed as an update, and invisible: the surviving row still looked like a well-formed answer. **This is the exact failure class the matrix exists to prevent, reproduced by the matrix itself.** Fixed by keying `(host_id, locus)`, which *keeps* the premise and corrects the key: the guest owns `(yolanda, in-guest)`, Windows owns `(yolanda, windows-host)`, and LWW returns to deciding only which of one writer's successive probes is current. Unkeyable rows are now reported in a skipped list, never dropped — a silently discarded row is indistinguishable from a host that never contributed.

**The general lesson, for whoever designs the next channel:** "one writer per key" is a claim about the WORLD, not about the code. It was wrong here for a reason no amount of reading the fold would reveal, and it surfaced within an hour only because the very next packet tried to use it. A design validated by its own tests and never by a second consumer is not yet validated.
