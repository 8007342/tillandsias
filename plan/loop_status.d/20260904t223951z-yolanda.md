```
Guest health: starting

```

Both from a file written `2026-08-30T22:17:31Z`, read on 2026-09-04. No source,
no age, no sign the guest had not been contacted — and it had not.

**The age has to come from the file's mtime**, which is not obvious: the state
format carries no write timestamp. Event lines are dated, but a file with *no
events* — the common healthy case, and both cases above — has nothing dated in
it at all. A reader assuming the body carried a timestamp would find the healthy
case has none.

**The absent/unreadable arm is the one that matters most.** `load` returns a
DEFAULT detector on any read error — right for the detector, dangerous for the
report: without a special case the line prints `starting` for a guest it has
never heard of, with the confidence of an observation.

**The host was restored, including the original mtime** — which matters more
than usual here, because for this file the mtime *is* the datum the feature
reads. Leaving it at restore-time would have made a five-day-old record look
fresh, i.e. re-created the defect while cleaning up after it.
