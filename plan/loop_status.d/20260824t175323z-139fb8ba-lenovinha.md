## Cycle — lenovinha (linux_immutable) 2026-08-24T17:53:23Z — I overstated my own gate's cost 100x, and the real number reverses the decision

Full-mode cycle. All guards green; daily gate current. No new packet claimed — the cycle went to auditing what I landed last cycle, which turned out to be necessary.

I MEASURED THE COST OF THE CROSS-TARGET GATE I ADDED TWO HOURS AGO. Closing 656-spux I recorded "a warm full-workspace cross-check 37s" and built a fleet-wide decision on it: 115 MiB of mingw plus 37s per gate run was too much to impose, so the check would SKIP where the toolchain is absent and hosts could opt in. I wrote that it was "not mine to decide".

THE RECURRING COST IS 0.3 SECONDS. Profiled directly (TILLANDSIAS_GATE_PROFILE=1): "0.3s Cross-target workspace check (656-spux)". Whole-gate wall clock 44s against a 38-40s baseline, which agrees. The 37s was the ONE-OFF first run after `rustup target add`, when cargo compiles every dependency for the new target once; steady state it does nothing because nothing changed. I measured the cold path and reported it as the warm one.

THAT IS NOT A FOOTNOTE, because the cost WAS the entire argument for leaving the gate opt-in. A check adding 0.3s to every run is a different proposition from one adding 37s, and I had made the expensive-sounding version the basis of a decision about the whole fleet. An overstated cost that discourages adoption of a gate which found a live trunk break on its first run is not a harmless rounding error.

SO I REVERSED IT, and flagged the reversal rather than quietly landing it. mingw64-gcc and the x86_64-pc-windows-gnu target are now in the tillandsias-builder init set, with _toolbox_initialized requiring both so pre-existing toolboxes fleet-wide re-run init and pick them up — the same pattern musl-gcc and jq/yq/rg/openssl used.

THE SIZE ARGUMENT ALSO SHRANK ONCE I MEASURED INSTEAD OF REACTING. 115 MiB reads as a lot in isolation; this toolbox already carries a 2.8 GB /usr and 1.9 GB ~/.rustup, so mingw is ~2% of an environment whose whole purpose is compiling. I had compared it against the 6.3 MiB jq/yq/rg/openssl addition, which is the wrong denominator — that says one addition is bigger than another, not whether either is big.

WHAT DOES NOT CHANGE: the script still SKIPS rather than fails when the toolchain is absent, and that stays right — not every host builds through the toolbox (macOS and mutable-Linux build natively), so skip remains the honest answer there and still names the exact missing binary. The init-set change grants the capability; it does not turn absence into failure anywhere. Reverting is one line if the operator disagrees, and the real numbers are in the ledger so that call can be made on them rather than on my first wrong one.
