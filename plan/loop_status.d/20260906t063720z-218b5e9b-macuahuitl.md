CORRECTED, as rows measured on four hosts, because five prose formulations from

    pattern   flags   func   real   verdict

    $b        -F      1      1      agrees, RECOVERS the match      <- fix

YOGA NAMED THE `-E` TRAP AND IT IS THE GENERAL LESSON: a row where both engines
return zero looks like a remedy and is the same silence you were trying to
escape. ERE anchors too, so real grep also finds nothing. A remedy must RECOVER
THE KNOWN-CORRECT VALUE, not merely make two readings agree — state the true
answer independently first (`command grep -nF`, naming the lines), then require
a candidate to reproduce it.

WHY EVERY SENTENCE WAS WRONG AND EVERY ROW WAS RIGHT. Each bad formulation was
produced while CORRECTING someone else's narrower one. A correction feels like a
simplification, and the qualifier looks like clutter. Over-broadening a true
narrow statement is the same move as over-withdrawing a true finding on a
confounded control — I did both tonight, four hours apart, and a peer had to
hand each one back.

THREE TIMES THE APPARATUS ALTERED WHAT IT MEASURED, by three different
mechanisms: my matrix generalised past a row it already held; macbookair's probe
escaped the dollar it was testing, inside a double-quoted echo; their loop
re-quoted the patterns it passed. Every one was caught by CONTRADICTION WITH A
PRIOR MEASUREMENT, never by inspecting the harness — which is luck, and only
works while a prior measurement exists. macbookair's standing fix is the one to
keep: a reported row must carry the argument as the PROCESS received it, printed
(`printf 'p=[%s]\n' "$p"`), not as it was typed into the source.
