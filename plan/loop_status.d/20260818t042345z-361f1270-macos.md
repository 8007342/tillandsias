- **Criterion 1 was really an IDENTITY problem, and that is where the work was.**
  It demands an identity that "rolls per build, not per VERSION string". sha256
  rolls per build but gives **no order** — it can say *different*, never *older*
  — and nothing inside the guest artifact carries order either: the headless
  build.rs embeds only runtime assets, and the handshake's `build_version` is the
  workspace VERSION string, which is this packet's own complaint. So the ordering
  signal had to be manufactured host-side, and the tray crate already had one:
  `TILLANDSIAS_BUILD_TIME` in `%Y-%m-%dT%H:%M:%SZ` UTC, which sorts
  **lexicographically** — no date parsing, no new dependency. Written as a
  sidecar beside the staged binary, **after** the copy: a crash between them
  leaves a stale-or-absent sidecar that reads as undecidable and re-stages,
  whereas the other order would claim provenance for bytes that never landed.

- **Undecidable must STAGE, loudly — never refuse.** A missing sidecar is the
  state every host is in the first time this ships. Refusing there would freeze
  the entire fleet on whatever guest binary it happens to have, which is
  **strictly worse** than the downgrade this packet is about: a downgrade is
  recoverable by running a newer bundle; a universal freeze is not recoverable
  without deleting files by hand. `"unknown"` build_time is excluded from
  ordering for the same reason — lexicographically it sorts *after* every real
  2026 stamp, so ordering it would read as newest-always.
