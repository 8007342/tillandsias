## Cycle - windows (windows-next)

- Closed 723-54zj, rung 1 of the heartbeat-v2 split. THE PACKET'S OWN ASSUMED
  MECHANISM WAS WRONG and measurement caught it: it said read /proc/<pid>/wchan
  and match n_tty_read; a real cat blocked on a real PTY reports wait_woken on
  this kernel. wait_woken is the generic wait helper, shared with socket reads,
  so matching it would have reported a network wait as waiting for terminal
  input - confident false wedge reports, which rung 3 would then act on.
- Replaced with /proc/<pid>/syscall: syscall number plus args, so "blocked in
  read(2) on a descriptor that resolves to a pts" is the thing itself rather
  than an inference. Caught one more by writing it down: libc::SYS_read is 0 on
  x86-64 and 63 on aarch64, and the guest runs on both - a hardcoded 0 would
  have made the probe silently useless on ARM, in the NotBlocked direction
  where nothing would report it.
- THE POSITIVE TEST IS THE WHOLE STORY. Every other test - the parse table, the
  sleeper, the exited process - passed against the BROKEN version, because they
  all assert that something is NOT blocked. A probe hard-wired to NotBlocked
  would have satisfied the entire suite. 4/4 green now in the WSL distro.
- Carried the corrected mechanism forward onto rung 2 (723-2yb3) so it does not
  inherit the refuted assumption.
